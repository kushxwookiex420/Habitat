## 4. Stage 4 — first live autonomous mission (owner or operator, authenticated)

Harmless, read-only, no adapter side effects. Replace `$B` and `$TOKEN` with the origin and the Ax
command token held outside this chat.

```bash
B=https://habitat-1-szzd.onrender.com
H="Authorization: Bearer $TOKEN"

# 1. Durable objective (deterministic key makes a retry idempotent)
curl -sS -X POST "$B/ax/command/objectives" -H "$H" -H 'content-type: application/json' -d '{
  "key": "mission-18-live-readonly-1",
  "objective": "Research the README.md evidence in this repository and audit the adapter allowlist",
  "criteria": ["Repository evidence cites README.md with evidence", "The adapter allowlist was audited"],
  "budgetUsd": 0.05
}'
# record .objective.id

curl -sS -X POST "$B/ax/command/objectives/$ID/understand" -H "$H" -H 'content-type: application/json' \
  -d '{"summary":"Research repository evidence and audit the adapter allowlist"}'

curl -sS -X POST "$B/ax/command/objectives/$ID/plan" -H "$H" -H 'content-type: application/json' -d '{
  "risk": "low",
  "steps": [
    {"objective":"Recall approved project memory for the mission","agent":"memory"},
    {"objective":"Gather citable evidence from README.md in the repository","agent":"research"},
    {"objective":"Audit the adapter allowlist and permissions","agent":"security"},
    {"objective":"Independently check the evidence against every criterion","agent":"verification"}
  ]
}'

# 2. Let the scheduler own it (this is the scheduler-driven proof)
curl -sS -X POST "$B/ax/command/scheduler/tick" -H "$H" -H 'content-type: application/json' \
  -d '{"trigger":"mission-18-live"}'
# expect .autonomy.objectives.advanced[] entry with id == $ID, ok true, missionStatus "completed"

curl -sS "$B/ax/command/objectives/$ID" -H "$H"
# expect status "completed", verification.verified true, criteria all met, evidence >= 4,
#        at least one evidence summary matching README.md#L<number>

curl -sS "$B/ax/command/messages?limit=50" -H "$H"
# find the message with metadata.objectiveId == $ID and kind "result"
```

**Restart survival:** Render → Manual Restart (or the next deploy), then repeat
`GET /ax/command/objectives/$ID` and the message read. A completed objective, its evidence and its
result message must still be present and identical; that proves D1 persistence across a restart.

**Stop / resume / revoke / recovery**, honestly scoped:

- `POST /ax/command/objectives/$ID/work/stop` records a durable stop; the cycle stops before its
  next step. A short mission may finish inside one tick before a stop can arrive, so use a second,
  longer mission if you need to observe `interrupted`.
- Resume: `POST /ax/command/objectives/$ID/recover`, then tick again. Completed step evidence is
  reused, not repeated.
- Revoke: `POST /ax/command/agents/revoke` refuses new agent steps for the process and raises an
  audit event. It is process-local; a restart clears it. Do this last, then restart.
- Recovery: an interrupted objective is recovered through the route above; there is no automatic
  completion.
